# Product A Authority and Boundaries

The [approved skill and workflow architecture delta](../superpowers/specs/2026-08-31-product-a-skill-workflow-contract-delta.md)
defines this hierarchy within one contract revision:

1. Approved Product A specification and approved architecture deltas own scope,
   safety, human gates, and component responsibilities.
2. Python typed domain models, policies, calculations, and validators own numeric
   truth, states, units, and deterministic gates.
3. Generated JSON Schemas derive serialized contracts from those models.
4. The adjacent [workflow-contract.yaml](../../skills/premarket-research/references/workflow-contract.yaml)
   owns premarket order, handoffs, bounded repair, invariants, and outcomes.
5. Each [SKILL.md](../../skills/README.md) owns its bounded trigger, allowed
   operations, loading rules, and output/failure/safety obligations.
6. Canonical synthesis prompt instructions shape a draft from a frozen packet.
7. Canonical report template owns deterministic Markdown presentation.
8. Immutable JSON run bundle owns the truth and recorded component versions for
   one frozen run.
9. Derived documentation, saved prompts, and rendered Markdown guide humans.
10. The master blueprint owns sequencing and review checkpoints.

This hierarchy does not rewrite history. A frozen bundle retains its original
evidence and component versions. Replay either uses compatible versions or fails
closed on drift; current documentation never changes a historical run.

The three canonical skills have one adjacent premarket manifest. There is no
global skill registry, workflow engine, or skill-local financial/provider script.
Installed premarket resource bytes produce the framed SHA-256 `skill_version`;
prompt and template versions remain separate. Source-checkout offline fixtures
explicitly inject their trusted synthetic component versions.

Typed application services own source authority, freshness, state transitions,
publication validity, and human-review status. Tool discovery establishes no
authorization. The current operational source scope is Alpaca market data and
the local market calendar; missing macro and event sources remain explicit.
No brokerage, automatic trade execution, production model adapter, or active
scheduling is enabled. Human review remains mandatory.
